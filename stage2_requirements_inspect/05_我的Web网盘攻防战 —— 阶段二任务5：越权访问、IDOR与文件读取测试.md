# 我的Web网盘攻防战 —— 阶段二任务5：越权访问、IDOR与文件读取测试

## 写在前面：能登录，不代表能看所有文件

网盘系统最核心的安全要求之一是：用户只能访问自己的文件。用户A上传的文件，用户B不能下载、删除、重命名，也不能通过改参数看到。本任务把三个高度相关的问题放在一起：越权访问、IDOR 和文件读取/路径穿越。

> **边界提醒**：本任务只允许在自己小组的网盘靶场、课程指定互测靶场、虚拟机或本机 `localhost` 中完成。不要扫描、爆破、上传、探测任何未授权网站、校园系统、云服务或他人真实业务系统。所有攻击动作都必须可回滚、可截图、可复现，不以破坏数据为目标。

## 第1步：准备两个用户和测试文件

创建两个普通用户：

```text
user1 / 123456
user2 / 123456
```

分别上传不同文件：

```text
user1 上传：user1_secret.txt，内容写“这是user1的文件”
user2 上传：user2_secret.txt，内容写“这是user2的文件”
```

测试越权时一定要用两个用户。不然你无法证明“访问了别人的资源”。

---

## 第2步：测试IDOR和水平越权

IDOR可以理解为：服务器把资源编号、用户名、文件名直接暴露给前端，而后端没有检查当前用户是否有权访问这个编号对应的资源。常见危险下载链接包括：

```text
/download?user=user1&filename=user1_secret.txt
/download?filePath=user1/user1_secret.txt
/download?fileId=1
```

测试步骤：登录 user1，复制自己的下载链接；退出或换浏览器登录 user2；在 user2 登录状态下访问 user1 的下载链接；观察是否能下载 `user1_secret.txt`；对删除、重命名、分享接口重复测试。

如果 user2 能下载 user1 文件，存在水平越权；如果 user2 页面没有按钮，但直接访问URL能成功，说明只做了前端限制；如果返回“无权限”或404，且日志中记录拒绝，较安全。

## 第3步：测试文件读取与路径穿越

很多同学会这样写下载接口：

```java
String fileName = request.getParameter("fileName");
String base = getServletContext().getRealPath("/upload/") + session.getAttribute("user");
File file = new File(base + "/" + fileName);
```

看起来已经把用户目录固定到当前Session了，但如果 `fileName` 是：

```text
../user2/user2_secret.txt
```

拼接后路径可能跳到上级目录，从而访问其他用户文件。课程中只测试你自己创建的课程文件，例如 `../user2/user2_secret.txt`。不要读取系统敏感文件、云服务器配置、密钥、真实用户数据。

测试步骤：登录 user1；正常下载 `user1_secret.txt`；将下载参数改成 `../user2/user2_secret.txt`；观察是否能下载user2文件；记录服务器日志中实际拼接的路径。

## 第4步：分析漏洞原因

越权与文件读取常见根因包括：后端相信了前端传来的 `user` 参数；下载链接里暴露了真实目录结构；只检查“是否登录”，没有检查“资源是否属于当前用户”；文件路径直接字符串拼接；没有对路径进行规范化和目录边界检查；删除、下载、预览接口各写各的，权限规则不一致。你要把漏洞对应到具体代码行。

---

## 第5步：修复越权与路径穿越

用户身份只能从Session取。危险做法是 `/download?user=user1&filename=a.txt`，更安全的设计是 `/download?filename=a.txt`，后端从Session获取当前用户。

如果使用数据库保存文件信息，查询时必须带归属条件：

```sql
SELECT * FROM files WHERE id = ? AND owner = ?
```

不要只查：

```sql
SELECT * FROM files WHERE id = ?
```

路径修复要先得到真实规范路径，再判断目标路径是否仍在用户目录下：

```text
base = realpath(upload_root/current_user)
target = realpath(base/fileName)
if not target starts with base:
    reject("非法路径")
```

下载、删除、预览、重命名、分享都要用同一套权限检查函数。不要下载修了，删除还漏着。

### 漏洞报告至少写清楚

- 漏洞类型：例如 SQL注入 / XSS / CSRF / 越权下载。
- 漏洞位置：完整 URL、接口路径、请求方法、关键参数。
- 测试环境：本机、虚拟机或课程互测靶场；测试时间；测试账号。
- 复现步骤：从登录、构造请求到观察结果，每一步都要截图或保存请求包。
- 影响说明：能造成什么后果，不能夸大；例如“可绕过登录进入文件列表”，不要写成“可控制服务器”。
- 修复建议：说明根因、给出修复方式，并附修复后同样步骤无法成功的证明。

### 修复时的共同原则

1. 不要只在前端过滤。浏览器里的限制都可以被 F12、代理工具或脚本绕过，后端必须做真正校验。
2. 不要只黑名单过滤某几个字符。优先采用白名单、参数化查询、框架内置安全机制、权限统一拦截。
3. 不要修一个接口漏一个接口。文件展示、下载、删除、重命名、分享等同类接口都要统一检查。
4. 修复后一定要用“原来的攻击参数”再测一遍，证明漏洞确实失效。

## 最后的提醒

权限问题没有“差不多安全”。只要有一个接口忘了检查资源归属，整个网盘就可能变成公共文件夹。任何资源操作都要回答两个问题：你是谁？这个资源是不是你的？
