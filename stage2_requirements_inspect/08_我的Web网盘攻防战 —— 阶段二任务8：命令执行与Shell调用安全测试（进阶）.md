# 我的Web网盘攻防战 —— 阶段二任务8：命令执行与Shell调用安全测试（进阶）

## 写在前面：不要让文件名变成服务器命令的一部分

有些同学为了实现高级功能，可能会让后端调用系统命令，例如解压文件、生成图片缩略图、打包下载多个文件、调用脚本统计文件信息。如果把用户输入直接拼进命令字符串，就可能产生命令注入。命令注入的风险比普通页面错误严重得多，因为它可能让攻击者在服务器上执行命令。本任务是进阶任务。没有系统命令调用功能的小组，可以阅读并完成“代码审计说明”，不需要强行添加危险接口。

> **边界提醒**：本任务只允许在自己小组的网盘靶场、课程指定互测靶场、虚拟机或本机 `localhost` 中完成。不要扫描、爆破、上传、探测任何未授权网站、校园系统、云服务或他人真实业务系统。所有攻击动作都必须可回滚、可截图、可复现，不以破坏数据为目标。

## 第1步：查找系统命令调用点

Python常见危险函数包括 `os.system(...)`、`os.popen(...)`、`subprocess.run(..., shell=True)`。Java常见危险函数包括 `Runtime.getRuntime().exec(...)`、`ProcessBuilder(...)`。并不是所有调用都危险。关键看：用户输入是否进入命令字符串，以及是否由Shell解释。检查上传后处理文件、下载前打包、图片/视频预览、文件搜索调用系统工具、自己写的调试接口。

如果项目没有此类功能，报告中写明：“本项目未使用系统命令调用，因此不做复现，只完成防御学习。”

---

## 第2步：判断用户输入是否进入命令

危险写法示例：

```python
filename = request.args.get("filename")
os.system("zip output.zip " + filename)
```

如果 `filename` 由用户控制，并且命令由Shell解析，攻击者可能通过特殊分隔符改变命令含义。更安全的方向是：

```python
subprocess.run(["zip", "output.zip", safe_filename], shell=False)
```

这里命令和参数分开传递，不让Shell重新解释整段字符串。

---

## 第3步：无害命令注入探测

课程只允许使用无害命令证明问题，例如：

```text
echo COURSE_CMD_TEST
whoami
pwd
```

不要执行下载、反连、删除、改权限、读取密钥、扫描内网等操作。如果某个参数被拼进命令，可以输入带有分隔含义的内容，观察是否出现额外输出。不同系统分隔符不同，本任务不要求背诵，重点是理解：当用户输入被Shell解释时，它就不再只是普通文件名。只要你看到 `COURSE_CMD_TEST` 出现在响应、日志或生成文件中，就说明风险存在。

---

## 第4步：分析漏洞原因

命令执行风险常见根因包括使用 `shell=True` 或等价方式，把用户输入拼进一整条命令字符串，文件名没有白名单或规范化，Web服务权限过高，错误信息和命令输出直接返回给用户，为了方便调试保留了“执行命令”的接口。如果项目没有命令调用，也要在报告中写出未来实现压缩/预览功能时的安全设计。

---

## 第5步：安全加固

能用语言标准库完成的功能，就不要调用系统命令。例如 Python 用 `zipfile` 打包，Java 用 `java.util.zip`。如果必须调用外部程序，使用参数数组，不拼接字符串：

```python
subprocess.run(["zip", "output.zip", safe_filename], shell=False, check=True)
```

如果用户只能选择压缩格式，就只允许固定值，例如 `zip` 或 `tar`，不要允许用户传任意命令选项。Web服务不要用root/管理员权限运行。错误日志可以写到服务端，但不要把系统命令错误、路径、环境变量直接返回给浏览器。

### 漏洞报告至少写清楚

- 漏洞类型：例如 SQL注入 / XSS / CSRF / 越权下载。
- 漏洞位置：完整 URL、接口路径、请求方法、关键参数。
- 测试环境：本机、虚拟机或课程互测靶场；测试时间；测试账号。
- 复现步骤：从登录、构造请求到观察结果，每一步都要截图或保存请求包。
- 影响说明：能造成什么后果，不能夸大；例如“可绕过登录进入文件列表”，不要写成“可控制服务器”。
- 修复建议：说明根因、给出修复方式，并附修复后同样步骤无法成功的证明。

### 修复时的共同原则

1. 不要只在前端过滤。浏览器里的限制都可以被 F12、代理工具或脚本绕过，后端必须做真正校验。
2. 不要只黑名单过滤某几个字符。优先采用白名单、参数化查询、框架内置安全机制、权限统一拦截。
3. 不要修一个接口漏一个接口。文件展示、下载、删除、重命名、分享等同类接口都要统一检查。
4. 修复后一定要用“原来的攻击参数”再测一遍，证明漏洞确实失效。

## 最后的提醒

命令执行漏洞的本质和SQL注入很像：用户输入不应该变成“可执行语法”。区别是SQL注入影响数据库，命令注入影响操作系统，后果往往更严重。能不用Shell，就不要用Shell。
