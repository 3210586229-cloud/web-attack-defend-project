# 阶段二逐项漏洞与加固记录

## 任务1：弱口令与密码爆破

**位置**：`/login`、`/register`、`/api/login`、`/api/register`。  
**修复**：注册密码至少8位且包含字母和数字，拒绝常见密码；同一IP/账号连续5次失败后锁定5分钟；统一错误提示并记录安全日志；旧明文密码成功登录后升级为哈希。  
**复测**：5次错误后正确密码返回401；弱密码注册返回400。

## 任务2：SQL注入

**审计结论**：登录、注册查询均使用 `%s` 参数绑定，未发现用户输入拼接 SQL。  
**预防性措施**：保留参数化查询和统一数据库访问审计。  
**复测**：代码审计证据见 `evidence/code_audit.txt`。

## 任务3：XSS

**审计结论**：使用 Jinja `render_template`，默认 HTML 转义；文件名下载链接使用 URL 编码。  
**预防性措施**：不使用 `|safe` 展示用户输入，限制文件名并避免脚本上下文拼接。  
**复测**：未执行脚本型 payload，代码审计证据见 `evidence/code_audit.txt`。

## 任务4：CSRF

**位置**：登录、注册、上传、删除及 API 状态变更接口。  
**修复**：Session 生成随机 CSRF Token；表单隐藏字段和 API `X-CSRF-Token` 均校验；缺失或错误 Token 返回403；Cookie 使用 SameSite=Lax。  
**复测**：缺少或错误 Token 的注册、上传请求均返回403。

## 任务5：越权、IDOR与文件读取

**审计结论**：文件目录由当前 Session 用户名决定，文件名通过 `secure_filename` 规范化并检查文件存在性。  
**预防性措施**：所有网页和 API 文件接口均使用当前会话目录，禁止客户端指定用户目录。  
**复测**：未登录访问返回302/401；双账号互测截图需在最终提交中补入。

## 任务6：文件上传、WebShell与木马识别

**位置**：`/upload`、`/api/files`。  
**修复**：限制请求总大小16MB；使用安全文件名；仅允许课程常见文件扩展名；危险扩展名上传返回400。部署时应将上传目录配置为不可执行。  
**复测**：`payload.exe` 上传返回400。

## 任务7：SSTI

**审计结论**：未发现 `render_template_string` 或将用户输入作为模板执行的代码。  
**预防性措施**：用户输入只能作为固定模板变量，禁止动态模板拼接。  
**复测**：代码审计证据见 `evidence/code_audit.txt`。

## 任务8：命令执行与 Shell 调用

**审计结论**：未发现 `os.system`、`os.popen`、`subprocess` 或 `shell=True`。  
**处理方式**：按进阶任务要求完成代码审计，不人为添加危险接口；未来如需压缩或处理文件，优先使用标准库，外部程序必须使用参数数组和 `shell=False`。  
**复测**：代码审计证据见 `evidence/code_audit.txt`。

## 任务9：会话管理与 Cookie

**修复**：配置 HttpOnly、SameSite=Lax 和可选 Secure；登录成功前清理旧 Session 并生成新的 CSRF 状态；退出时服务端 `session.clear()`；核心接口统一认证。  
**复测**：退出后访问 `/api/files` 返回401，未登录访问 `/profile` 重定向 `/login`。
