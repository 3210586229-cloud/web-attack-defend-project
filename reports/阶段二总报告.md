# 我的 Web 网盘攻防战：阶段二安全加固总报告

## 1. 项目与范围

- 测试对象：本机 Flask 网盘项目
- 主要服务文件：`gets.py`
- 数据库：MySQL `account_id`，仅使用课程测试账号
- 测试日期：2026-08-30
- 测试原则：本机、低速、无害、可回滚

## 2. 九项任务结论

1. **弱口令与密码爆破**：发现历史账号存在明文弱密码，修复注册密码策略、失败锁定、统一提示、日志，并在成功登录时升级历史密码哈希。
2. **SQL注入**：审计登录和注册 SQL，均采用参数绑定；未发现字符串拼接 SQL。
3. **XSS**：模板由 Jinja 渲染并默认转义；文件名链接增加 URL 编码；未执行脚本型 payload。
4. **CSRF**：状态变更接口增加服务端 Token，错误或缺失 Token 返回403。
5. **越权/IDOR/文件读取**：文件操作绑定当前会话用户目录，文件名经过规范化；双账号访问、路径穿越和跨用户删除均返回404。
6. **文件上传**：增加扩展名白名单、16MB请求限制、`secure_filename` 和图片/PDF/压缩包等文件头校验；上传目录部署时还应禁止脚本执行。
7. **SSTI**：未发现用户输入进入模板解析的危险调用。
8. **命令执行**：未发现系统命令调用；按任务要求完成代码审计，不添加危险接口。
9. **会话与Cookie**：启用 HttpOnly、SameSite=Lax，可选 Secure；浏览器证据显示登录前后 Session 值变化，退出后核心接口返回401。

## 3. 已知残留事项

- 生产环境必须设置高熵 `FLASK_SECRET_KEY`，不能依赖每次进程启动生成的临时值。
- HTTPS 部署时设置 `FLASK_COOKIE_SECURE=1`。
- 任务九外部 Cookie/登出截图和视频已归档到 `evidence/task9/`，本地双账号及 Cookie/Session 复测截图已归档到 `evidence/screenshots/`。
- 现有数据库中的弱密码账号应要求用户重置密码；代码仅在成功登录时透明升级哈希，不能把弱密码自动变强。
